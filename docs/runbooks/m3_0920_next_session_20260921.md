盘前必须从**清理完成后的基线**开始检查 TD 写入恢复；不能用一条历史上的旧错误
永久阻塞后续验收。操作者必须显式提供清理完成时间（不能猜测）：

```bash
: "${CLEANUP_BASELINE:?set CLEANUP_BASELINE to the actual cleanup completion time}"

TD_SPACE_ERRORS="$(journalctl -u t1-v2-live --since "$CLEANUP_BASELINE" --no-pager \
  | grep 'stage=commit.tdengine.*No enough disk space' || true)"
if [ -n "$TD_SPACE_ERRORS" ]; then
  echo 'TD_WRITE_HEALTH=BLOCKED'
  echo "$TD_SPACE_ERRORS"
else
  PROGRESS_LINES="$(journalctl -u t1-v2-live --since "$CLEANUP_BASELINE" --no-pager \
    | grep 't1_v2 progress' | tail -2 || true)"
  echo "$PROGRESS_LINES"
  if [ "$(printf '%s\n' "$PROGRESS_LINES" | sed '/^$/d' | wc -l)" -lt 2 ]; then
    echo 'TD_WRITE_HEALTH=UNPROVEN'
    # No fresh successful batch after cleanup: do not infer TD health from
    # systemd active state or from an old progress line.
  elif ! printf '%s\n' "$PROGRESS_LINES" | grep -q 'last_ts_ms=' \
      || ! printf '%s\n' "$PROGRESS_LINES" | grep -q 'td_sql='; then
    echo 'TD_WRITE_HEALTH=UNPROVEN'
  else
    echo 'TD_WRITE_HEALTH=NO_NEW_SPACE_ERROR_WITH_FRESH_PROGRESS'
  fi
fi
```

发现空间错误时不执行删除、prune、keep 变更或服务重启；本运行单只允许记录
`BLOCKED/WARN`，等待单独批准的容量/保留策略处置。
受控窗口内没有新的 progress/heartbeat 时，同样不得把 systemd `active` 解释为
实时消费健康。
