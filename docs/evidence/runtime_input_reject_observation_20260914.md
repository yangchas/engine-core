## 解释边界

- `source_reject` 是 t1-v2 日志中的累计输入拒绝计数；当前证据没有把它拆分到具体 vendor 字段、decode 分支、symbol 或交易日，根因保持 `UNKNOWN`。
- `reject` 是另一累计计数，不能在没有源码/consumer 对照前与 `source_reject` 合并解释。
- `last_reject` 只表示该进度采样区间的增量计数；它不是 Rabbit 丢失数，也不能据此推导 ACK 丢失。样本中 `ack_fail=0`，但不等价于 source 完整性通过。
- `wall_lag_ms` 在 09:25 后继续增大，和拒绝计数同时存在；两者相关性和因果关系尚未证明。

## 对 Core 替代的影响

该观测加入多交易日容量与输入完整性 Gate：替代前必须取得 source reject 的分类/处理语义，或明确将其作为不可观测边界；Core 不得把 t1-v2 进度行当作完整 Rabbit/Gateway 证据，也不得自行修复或重放被拒绝输入。

生产安全计数保持：新增 consumer=0、ACK 改动=0、Redis/TD 写入=0、服务重启=0。
