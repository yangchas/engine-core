## Producer boundary correction

The 09:15–09:40 TD replay is valid stock-tick/cross-sectional evidence, but it
does not execute t1-v2's Q2 derivation. Q2 is produced by t1-v2's stateful
quote calculator and serialized by its Redis writer. A Q2-dependent replay must
use a Q2Frame generated by the same t1-v2 replay input; copying fields from
`stock_tick_v2` or using a postmarket Redis snapshot is not equivalent.

The deployed t1-v2 binary exposes a read-only validation path:

```text
--replay --start ... --end ... --dry-run --q2frame <validation/q2frame.jsonl>
```

The first smoke run succeeded for 2026-09-18 09:15:00–09:15:03 with
`TDENGINE_HOST=127.0.0.1`, one source batch, 3,278 ticks, `redis=skip`,
`tdengine=skip`, and a local `Q2FrameV1` artifact. This proves the producer
bridge is callable without production writes; it is not yet a complete
09:15–09:40 joint replay. Q2Frame source timestamps are accepted as producer
times rather than a Core market-hours gate.
